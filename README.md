# itmo_cv_course

В этой ветке содержится решение 4-его ДЗ по курсу CV. Задача данного ДЗ состоит в реализации двух алгоритмов трекинга перемещающихся объектов по их bbox'ам - tracker_soft и tracker_strong. В качестве объектов детекции выступают кантриболы (кол-во опционально), для каждого их которых генерируется путь с bbox'ом (возможно пустой или сдвинутый, с обозначенной вероятностью).

Необходимо выбрать целевые метрики оценки качества и замерить оба реализованных метода на разных конфигурациях кантриболов.

Все задачи успешно решены, исходный код решения предоставлен fastapi_server.py

## Tracker soft

Реализация начинается с имплементации tracker_soft, основанного на евклидовом расстоянии между центрами bbox'ов объектов, выбранного из-за его низкой вычислительной сложности, что соответствует ограничению на использование минимальных ресурсов. 

На каждом кадре вычисляется матрица стоимостей (cost_matrix), содержащая расстояния между центрами активных треков с предыдущего шага и центрами текущих обнаружений. Затем применяется венгерский алгоритм для оптимального сопоставления треков и обнаружений на основе вычисленных расстояний, отбрасывая пары с расстоянием выше заданного порога. Успешно сопоставленные треки обновляют свое положение и сбрасывают счетчик пропущенных кадров, при этом соответствующим обнаружениям присваивается существующий идентификатор трека. Для ненайденных треков увеличивается счетчик пропущенных кадров, и трек удаляется при превышении порога MAX_AGE_SOFT. Обнаружения, не нашедшие соответствия среди активных треков, инициализируют новые треки с уникальными идентификаторами.

Подход показывает крайне высокую скорость работы, а также достаточное качество (см. эксперименты).

## Tracker strong

Для повышения надежности отслеживания, особенно при наличии шума в детекциях и временных пропусков, `tracker_strong` реализуется с использованием **Фильтра Калмана** для каждого активного трека. Перед сопоставлением на каждом кадре, фильтр Калмана *предсказывает* ожидаемое положение и размер (`bounding box`) каждого трека, основываясь на его предыдущем состоянии и модели движения (например, постоянной скорости). Затем вычисляется матрица стоимостей на основе метрики IOU между этими *предсказанными* рамками треков и рамками объектов, *обнаруженных* детектором на текущем кадре (стоимость равна `1 - IoU`).

Оптимальное назначение обнаружений предсказанным трекам находится с помощью венгерского алгоритма, учитывая только пары с IoU выше порога `IOU_THRESHOLD_STRONG`. Для успешно сопоставленных пар состояние фильтра Калмана соответствующего трека **обновляется** с использованием данных реального обнаружения, корректируя оценку положения и скорости объекта. Обнаружения, не нашедшие соответствия среди предсказанных треков, инициируют создание новых треков, каждый из которых получает собственный фильтр Калмана. Треки, не получившие сопоставления в течение `MAX_AGE_STRONG` кадров, считаются потерянными и удаляются.

Этот подход, использующий предсказание движения и сглаживание измерений фильтром Калмана, обеспечиваеть значительно более стабильное и точное отслеживание по сравнению с tracker_soft.

## Метрики

Для оценки качества реализованных трекеров вычисляются две ключевые метрики на основе сравнения присвоенных track_id с истинными cb_id:
- Метрика ID Switches подсчитывает количество случаев, когда одному и тому же реальному объекту (cb_id), видимому на двух последовательных кадрах, были присвоены разные идентификаторы трека (track_id), отражая стабильность присвоения ID. Ниже - лучше
- Метрика Average Fragments Per Track измеряет среднее число уникальных track_id, полученных одним реальным объектом (cb_id) за все время его существования в видео, характеризуя непрерывность отслеживания. Ниже - лучше

Обе метрики используют ground truth данные (cb_id) для вычислений уже после работы трекера. Низкие значения обеих метрик указывают на более высокое качество отслеживания, стремясь к нулю для ID Switches и к единице для Average Fragments. Эти показатели позволяют количественно сравнить эффективность tracker_soft и tracker_strong в различных условиях.

Для каждого из необходимого количества кантриболов (5, 10, 20) были проведены эксперименты со следующими параметрами:
- random_range (rr) = 10, bb_skip_percent (bb) = .5
- random_range (rr) = 5, bb_skip_percent (bb) = .25
- random_range (rr) = 3, bb_skip_percent (bb) = .1                                                                                          |

Полученные метрики показывают, что tracker_strong последовательно демонстрирует лучшую производительность по сравнению с tracker_soft во всех протестированных сценариях, имея значительно меньшее количество переключений ID и более низкую фрагментацию треков. Увеличение количества объектов приводит к ухудшению показателей обоих трекеров, однако tracker_soft показывает меньшую степень деградации метрик.

Наблюдение: эксперименты на конфигурации random_range (rr) = 10, bb_skip_percent (bb) = .5 показывают лучшие результаты, чем на random_range (rr) = 3, bb_skip_percent (bb) = .1. Возможное объяснение состоит в том, что если bb_skip_percent высокий (50%), то вероятность того, что объект будет пропущен на кадре f или f-1, значительно возрастает. Это означает, что будет меньше пар последовательных кадров, где объект присутствует и там, и там, и где можно было бы зафиксировать ID Switch. Таким образом, общее количество измеренных свитчей может упасть, даже если трекинг в целом стал менее стабильным.

Эксперименты показали, что tracker_string, основанный на фильтре Калмана, стабильно превосходит tracker_soft, использующий расстояние евклида в качетсве основной метрики.
